# 设计：按本地日期切分输出文件（每日一套）

状态：**设计已定，实现中**。本文是 `grill-me` 那轮问答的结论，逐条对应到实现；
每个决定后面写的是"为什么"，因为其中三条是拿这台机器上的实测数字换来的。

术语：**一套（set）** = 一次"当日文件"的全部产物 —— 300 个 baseline 文件 + 4 个
sidecar，共 304 个文件，同一个前缀。**套前缀** = `%Y%m%d_%H%M%S`（本地时区）。

## 1. 行为

1. **目录不变，只换文件名前缀**。进程启动时建的那一个运行目录不变；跨本地零点时，
   关闭当前套、按新的一天建新的一套。每套：

   ```text
   <prefix>baseline_0000_j00_k00.bin   complex64[ntime][n_freq]
   ...
   <prefix>rows_ms.bin                 int64 LE Unix 毫秒，每行一条
   <prefix>rows_ms.txt                 "<row_index> <ms>" 每行一条（派生视图）
   <prefix>blocks.csv                  row_index, station, first_frame_id, n_cum, valid, zero_filled
   <prefix>metadata.yaml               自描述：配置 + 几何 + config_hash + 本套起始行号/帧号 + 时区 + 类型
   ```

2. **套前缀 = 该套第一条行的起始时刻**，按本地时区格式化：日期与时间取自**同一个时刻**
   （即 `rows_ms` 里那条，也就是该行第一个帧的墙钟），所以名字与内容不可能自相矛盾。
   因此每套的 `HHMMSS` 不固定：跨零点那套可能是 `000000`、`000001`，进程当天启动的那套
   是启动后第一条行的时刻。实测跨零点那次叫 `20260917_000000`，而启动那套叫
   `20260916_235907`。

3. **归属按行的起始时刻**：起始 < 本地零点 → 旧套（旧套最后一行可能延伸到零点后约一个
   行周期）；起始 ≥ 零点 → 新套。行不拆、不丢、不重，`n_cum` 与 `/n_cum` 归一化不变。

4. **每天一套**：一天只有一个前缀。当天重启 → 扫目录找到当日那套，校验几何与
   `config_hash` 后**追加**（前缀保持原样，不改名）；当日还没有 → 新建。
   续写的前提是**两次进程用同一个运行目录**：`run.name` / `--run-name` 要稳定，因为默认按
   时间戳命名，每个进程都会建新目录，那样"当日那套"就无从谈起（实测：`--run-name daily`
   两次，第二次认出当日那套 195 行、续写到 341 行；目录里始终一套，`first_row_index`
   没被改写，`rows_ms` 跨重启单调）。

5. **当日改了配置**（`config_hash` 不符，追加会把两种几何混进一套）：默认**拒绝启动**，
   错误信息里给出补救开关；显式开关才继续：`--allow-second-set`（当日另开一套，
   `metadata.set_kind: second_set`）或 `--set <prefix>`（显式指定续写哪一套）。
   哈希不符时**绝不静默追加**。

## 2. 时间

6. **本地时区**由 `localtime_r` 决定，遵 `TZ` 与 `/etc/localtime`，判定时现读。
   DST 的 23/25 小时一天自然正确，因为归属是"每行自己的本地日期"，不是"启动时刻 +
   n×86400 s"。

7. **只前进不回退**：一旦当前套已经是某一天，行时间戳回退（NTP 回跳、改时区）**不会**
   回切到旧的一天，只记一条警告并继续写当前套。理由：回切会产出两套交叉的数据，而
   `row_index` 是全局单调的。

8. **每行判定，不需要守夜定时器**（对 grill 结论的一处实现简化，写在这里以免后人困惑）：
   切套只可能由"来了一行"触发，没有行就没有数据要归属；所以"单调时钟守夜 + 期限对墙钟"
   退化成"写每行前用该行的 `row_ms` 算本地日期"。守夜定时器唯一的额外作用是发现时钟异常，
   而这由第 7 条（只前进不回退 + 警告）覆盖。

9. **目录名也改成本地时间**：`corr_%Y%m%d_%H%M%S`（原来是 `gmtime_r` 的 UTC）。
   启动日志同时打印本地与 UTC 时间，避免与历史（UTC）目录混读。

## 3. 切套机制

10. **同步切套，接受一次约 0.5 s 的停顿**。实测（`/scratch`，本机）：

    | 操作 | 代价 |
    |---|---|
    | 建 304 个文件（create+写+close） | **422 ms** |
    | 逐个 fsync 304 个文件 | 56 ms |
    | 304 次 rename（"预建+改名"路线） | **432 ms** —— 不比新建便宜，所以不做预建 |

    接收侧余量 = 环领先 105 ms + socket 640 ms ≈ **745 ms**，所以 0.5 s 在余量之内，
    但 load 20–30 时元数据操作可能慢 2–3 倍。**这是一条被接受的风险**，实测（§5 的脚本，
    24 站、把本地零点挪进窗口）：

    | 注入速率 | 行周期 | 切套的文件工作 | 跨零点后的补零 |
    |---|---|---|---|
    | 20 kpps（管线有余量）| 9.78 s | 532 ms | **0 帧**（整场 0.0000%）|
    | 50 kpps（管线贴极限）| 3.92 s | 488 ms | 紧跟边界的那一行掉 3082/48896 = **6.3%**（整场 0.0196%）|

    所以在生产几何（1 s 积分 = 1.0014 s 行周期）下，切套的代价是**一行的一个零头**，
    而且那一行自己就把缺失帧数记在 `blocks.csv` 里；行周期越长越看不出来。要更小就得
    走 §3 第 10 条之外的路线（异步切套 / 改输出形状）。

11. **失败处理**：建新套/关旧套失败 → 有界重试（3 次 × 100 ms），仍失败则作为一条**新的
    停止原因**（`RunStop` 里新增，沿用"唯一停止原因、首个胜出"）写进报告并退出非零。
    绝不"继续往旧套里写"（那会让旧套的日期名与内容不符，对按天取数的下游是静默错数据）。

12. **切套时对旧套 flush + fsync + close**，与 `fsync_every_rows` 无关（边界处必须落盘）。
    `fsync_on_stop` 的语义不变（正常退出时对当前套再做一次）。

## 4. 数据契约

13. **`row_index` 继续全局**（与帧网格同一套编号，跨套不回零）；每套的 `rows_ms.bin`
    偏移从 0 开始；`first_frame_id` 仍在每行里，所以跨套拼接按
    `row_index` 或 `first_frame_id` 都行，现有工具（`compare_runs.py` 按 `first_frame_id` 配对）
    不用改。

14. **每套一份完整、自描述的 `metadata.yaml`**：原有 config dump + 几何 + `config_hash`
    之外，增加

    ```yaml
    set_prefix: 20260917_000001
    set_kind: rollover | start | resume | second_set
    set_continuation_of: 20260916_235959   # rollover/resume 才有
    first_row_index: 55247                 # 本套第一行的全局 row_index
    first_frame_id: 2700736000             # 本套第一行的 first_frame_id
    rows_at_open: 0                        # resume 时本套已有的行数
    local_timezone: Asia/Shanghai          # TZ 环境变量值
    local_utc_offset_s: 28800              # 建套时刻的本地偏移
    ```

    读端因此不需要扫目录就能知道一套数据接在哪一行之后、属于哪一天。

15. **不做完整性标记**（不写 `_CLOSED`、不做"临时前缀+改名"）：读端自行按"日期是不是
    今天 / 进程是否还在跑"判断。**被接受的代价**：崩溃那天的套会永久残缺，却看起来像
    完整的一天；只有人工核对 `blocks.csv` 的行数与 `row_index` 连续性才能发现。

16. **`daily_files` 默认开，对所有运行生效**（回放与短跑同样按日命名），可关：
    `storage.daily_files: false` 回到"目录里只有不带前缀的文件"的老行为；
    前缀格式可配 `storage.file_prefix_format`（默认 `"%Y%m%d_%H%M%S"`）。

## 5. 验收判据

`tools/daily_rollover_test.sh` 用 POSIX TZ 字符串把**本地零点挪进测试窗口**
（例：`TZ="UTC-14:57"` 表示 UTC+14:57，可以把"现在"映射到本地 23:58:30），跑真跨零点
5–10 分钟，然后逐条检查：

1. **套数与名字**：跨零点后目录里出现第二套，且两套前缀的日期不同；每套前缀的日期与
   `HHMMSS` = 该套 `metadata.yaml` 的 `first_row_index` 那一行在 `rows_ms.bin` 里的本地
   时间（逐字节对照，不是"看起来对"）。
2. **行不丢不重**：两套的 `blocks.csv` 行数之和 = 运行的 `rows closed` 数 = 进程报告的
   总行数；`row_index` 跨套连续且不回零。
3. **帧网格连续**：第二套的 `first_frame_id` = 第一套最后一行 `first_frame_id + n_cum`。
4. **时间单调**：第二套的 `rows_ms.bin` 第一条 > 第一套最后一条；跨套合并后严格单调。
5. **归属正确**：第一套最后一行的 `rows_ms` 转换成本地时间 < 零点；第二套第一行的 ≥ 零点。
6. **切套代价**：脚本自己盯着目录（每 10 ms）测三件事 —— 旧套最后一次写入、新套第一个
   文件出现、新套 304 个文件齐全 —— 再**减去行周期**（行周期是注入速率决定的，不加这一步
   会把"下一行本来就还没到"算成停顿：第一次量出 9.8 s 的"停顿"就是这么来的）。同时打印
   跨零点前后各 3 行的逐行补零（判据是逐行，不是汇总）。
   注意**不能用文件 mtime 与墙钟相减**：本机共享的 `/scratch` 报出来的 mtime 比墙钟慢约
   13 分钟，混用会凭空造出 13 分钟的"停顿"。
7. **单测**：日边界判定抽成纯函数（输入墙钟时刻/当前套 → 输出用哪个前缀/是否该切/是否只
   警告），覆盖：正中零点、零点前 1 ms、零点后 1 ms、DST 的 23/25 小时日、时间回退。

| 文件 | 改动 |
|---|---|
| `corr-rs/src/config.rs` | `utc_stamp()` → `local_stamp(fmt)`；`StorageCfg` 增 `daily_files` / `file_prefix_format` + 校验；目录名用本地时间 |
